Ship.

appship은 release/ 폴더 하나로 iOS와 Android 앱을 App Store와 Google Play에 릴리스합니다. fastlane 위에서 동작하므로 더 이상 Fastfile을 직접 관리할 필요가 없습니다.

$ npm i -g appship-ai
통합 가이드 읽기

워크플로

빈 저장소에서 App Review까지, 명령어 다섯 개.

프로젝트마다 한 번 설정하고 전체를 점검한 뒤, 릴리스할 때마다 마지막 두 명령어만 반복하면 됩니다.

  1. 프로젝트당 한 번 appship init

    프레임워크, bundle id, package name을 감지한 뒤 주석이 달린 템플릿으로 release/를 생성하고 .gitignore를 업데이트합니다.

  2. 업로드 전마다 appship doctor

    도구, 키, 글자 수 제한, 이미지 크기, 자리 표시 텍스트를 점검하고, 키가 git에 커밋되어 있으면 실패 처리합니다.

  3. 최초 1회 appship first-release

    iOS 앱을 생성하고 스토어 등록 정보와 App Privacy를 올리며, 스토어에서 수동으로만 할 수 있는 단계는 CHECKLIST.md로 정리합니다.

  4. 릴리스마다 appship upload --build

    빌드 명령어를 실행한 뒤 .ipa는 TestFlight에, .aab는 Play 트랙에 단계적 출시와 함께 업로드합니다.

  5. 릴리스마다 appship submit

    확인을 받은 뒤 iOS 빌드를 App Review에 제출하고 Android 릴리스를 production으로 승격합니다.

자동화 범위

스토어가 도구에 허용하는 범위, 솔직하게 말씀드립니다.

Apple과 Google은 일부 단계를 의도적으로 수동으로 남겨 둡니다. appship은 두 회사의 API가 허용하는 범위를 자동화합니다. 나머지는 답변이 미리 채워진 체크리스트로 제공합니다.

  • 자동 appship이 처리
  • Apple ID 2FA 로그인이 필요하므로 CI에서는 사용할 수 없음
  • 체크리스트 API 없음, 답변을 콘솔에 복사해 입력

Google Play에서는 첫 번째 번들을 직접 업로드해야 합니다. 새 개인 개발자 계정은 production 출시 전에 테스터 12명과 14일간 비공개 테스트도 거쳐야 합니다.

기능

바이너리 주변의 모든 작업을 알아서 처리합니다.

프로젝트당 설정 하나

앱 저장소에는 release/ 폴더만 추가됩니다. 릴리스 로직은 도구 안에 있으므로 appship을 업데이트하면 이를 사용하는 모든 프로젝트가 함께 업데이트됩니다.

release/release.yml
app:
  name: "Word Bank"
  primary_locale: en-US
ios:
  bundle_id: com.ketch.wordbank
  artifact: "build/ios/ipa/*.ipa"
  build_command: "flutter build ipa --release"
android:
  package_name: com.ketch.wordbank
  track: internal
  rollout: 1         # 0.2 = 20% staged rollout
credentials:
  profile: ketch-studio

스토어 질문, 한 번만 답하세요

연령 등급, 수출 규정 준수, 콘텐츠 권리, 심사 담당자 연락처. 답변을 questionnaire.yml에 작성하면 appship이 API로 가능한 항목은 채우고 나머지는 CHECKLIST.md에 정리합니다.

release/questionnaire.yml
ios:
  export_compliance:
    uses_non_exempt_encryption: false
  content_rights:
    uses_third_party_content: false
  age_rating:
    gamblingSimulated: NONE
    violenceCartoonOrFantasy: NONE
    messagingAndChat: false
    ageAssurance: false

doctor가 스토어보다 먼저 잡아냅니다

글자 수 제한, 잘못된 URL, 남아 있는 TODO, 잘못된 이미지 크기, 오래된 아티팩트, 누락된 키까지. 모든 문제에 해결 방법이 함께 표시됩니다.

appship doctor
▸ iOS · store listing
  ✗ ios/metadata/en-US/subtitle.txt is 34 characters (max 30)
  ! ios/screenshots/vi has no 6.9"/6.5" iPhone screenshot
▸ Android · store listing
  ✗ images/icon.png is 1024x1024, expected 512x512

  ✗ 2 error(s), 1 warning(s)

AI 에이전트가 스토어 콘텐츠 초안을 작성합니다

Claude Code, Codex, Antigravity용 번들 스킬이 모든 언어로 릴리스 노트를 작성하고, 스토어 규격에 정확히 맞는 스크린샷을 만들고, 코드를 바탕으로 스토어 질문에 답변을 채웁니다. 스킬은 release/ 안에만 파일을 쓰며, 사용자가 검토한 뒤 push합니다. appship 자체는 AI를 호출하지 않습니다.

appship skills
▸ Claude Code: .claude/skills/
  ✓ app-content  installed
  ✓ release-notes  installed
  ✓ store-screenshots  installed
▸ Codex + Antigravity: .agents/skills/
  ✓ store-screenshots  installed
    Run: $store-screenshots (Codex)

키는 git 밖에 둡니다

키는 환경 변수, release/keys/(gitignore 처리), 권한 600으로 저장된 ~/.appship의 프로필 순으로 찾습니다. 비밀번호는 --dry-run에서 마스킹됩니다.

어떤 스택에서도 동작

appship은 빌드 명령어를 실행하고 .ipa와 .aab를 찾아 사용합니다. Flutter, React Native, Cocos Creator, 네이티브 프로젝트는 init 시 자동으로 감지됩니다.

쓰기 전에 먼저 확인

제출, production 반영, 라이브 등록 정보 덮어쓰기는 모두 확인을 요청합니다. CI에서는 --yes를 명시적으로 전달하세요.

CI 지원

.p8 키를 일반 텍스트 또는 base64로 APPSHIP_ASC_KEY에 전달하세요. 바로 쓸 수 있는 GitHub Actions 워크플로가 통합 가이드에 있습니다.

출시할 준비 되셨나요?

appship은 npm으로 배포됩니다. Node.js 22 이상, fastlane, 그리고 iOS 빌드를 위한 macOS가 필요합니다(Android는 Linux에서도 동작합니다).

$ npm i -g appship-ai

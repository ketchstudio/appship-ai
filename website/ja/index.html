Ship.

appship は、iOS と Android のアプリを 1 つの release/ フォルダから App Store と Google Play にリリースします。fastlane 上で動くので、Fastfile を自分で管理する必要はもうありません。

$ npm i -g appship-ai
導入ガイドを読む

ワークフロー

空のリポジトリからアプリ審査まで、5 つのコマンド。

セットアップはプロジェクトごとに 1 回だけ。すべてを確認したら、リリースのたびに最後の 2 つを繰り返します。

  1. プロジェクトごとに 1 回 appship init

    フレームワーク、bundle id、package name を検出し、コメント付きのテンプレートを含む release/ を作成して .gitignore を更新します。

  2. アップロードの前に毎回 appship doctor

    ツール、キー、文字数制限、画像サイズ、プレースホルダーの文言を確認し、キーが git にコミットされていればエラーにします。

  3. 初回のみ appship first-release

    iOS アプリを作成し、ストア掲載情報と App Privacy を送信して、ストア側で手作業が必要な手順を CHECKLIST.md にまとめます。

  4. リリースごとに毎回 appship upload --build

    ビルドコマンドを実行し、.ipa を TestFlight に、.aab を Play のトラックにアップロードします。段階的公開にも対応しています。

  5. リリースごとに毎回 appship submit

    確認のあと、iOS ビルドをアプリ審査に提出し、Android のリリースを本番へ昇格します。

自動化の範囲

ストアがツールに許していることを、正直にお伝えします。

Apple と Google は、意図的に手作業のままにしている手順があります。appship は、各社の API が許す範囲を自動化します。 それ以外は、あなたの回答をあらかじめ入力したチェックリストとして提供します。

  • 自動 appship が実行します
  • Apple ID 2FA 付きのログインが必要なため、CI では実行できません
  • チェックリスト API がないため、回答をコンソールにコピーします

Google Play では、最初のバンドルだけは手動でアップロードしてください。また、新しい個人向けデベロッパーアカウントでは、本番公開の前に 12 人のテスターによるクローズドテストを 14 日間行う必要があります。

機能

バイナリ以外の作業は、すべてお任せください。

プロジェクトごとに設定は 1 つ

アプリのリポジトリに追加されるのは release/ フォルダだけです。リリースのロジックはツール側にあるため、appship を更新すれば、それを使うすべてのプロジェクトが更新されます。

release/release.yml
app:
  name: "Word Bank"
  primary_locale: en-US
ios:
  bundle_id: com.ketch.wordbank
  artifact: "build/ios/ipa/*.ipa"
  build_command: "flutter build ipa --release"
android:
  package_name: com.ketch.wordbank
  track: internal
  rollout: 1         # 0.2 = 20% staged rollout
credentials:
  profile: ketch-studio

ストアの質問は、一度答えるだけ

年齢制限、輸出コンプライアンス、コンテンツの権利、審査担当者の連絡先。回答を questionnaire.yml に書いておけば、appship が API で可能な部分を入力し、残りを CHECKLIST.md にまとめます。

release/questionnaire.yml
ios:
  export_compliance:
    uses_non_exempt_encryption: false
  content_rights:
    uses_third_party_content: false
  age_rating:
    gamblingSimulated: NONE
    violenceCartoonOrFantasy: NONE
    messagingAndChat: false
    ageAssurance: false

ストアより先に doctor が問題を見つけます

文字数制限、無効な URL、消し忘れの TODO、誤った画像サイズ、古いアーティファクト、不足しているキー。どの問題にも対処方法が添えられます。

appship doctor
▸ iOS · store listing
  ✗ ios/metadata/en-US/subtitle.txt is 34 characters (max 30)
  ! ios/screenshots/vi has no 6.9"/6.5" iPhone screenshot
▸ Android · store listing

  ✗ 2 error(s), 1 warning(s)

キーを git に残さない

キーは、環境変数、release/keys/(gitignore 済み)、モード 600 で保存された ~/.appship 内のプロファイルの順に解決されます。パスワードは --dry-run ではマスクされます。

どんな技術スタックにも対応

appship はビルドコマンドを実行し、.ipa と .aab を自動で取得します。Flutter、React Native、Cocos Creator、ネイティブのプロジェクトは init 時に検出されます。

書き込む前に確認

提出、本番へのプッシュ、公開中の掲載情報の上書きは、いずれも確認を求めます。CI では --yes を明示的に指定してください。

CI にそのまま使える

.p8 キーは、プレーンテキストまたは base64 で APPSHIP_ASC_KEY に渡します。すぐ使える GitHub Actions のワークフローは導入ガイドに掲載しています。

リリースの準備はできましたか?

appship は npm で配布されています。必要なのは Node.js 22 以上、fastlane、そして iOS ビルド用の macOS です(Android は Linux でも動作します)。

$ npm i -g appship-ai

appship publie votre app iOS et Android sur l'App Store et Google Play à partir d'un seul dossier release/. Il s'appuie sur fastlane : vous n'avez plus jamais de Fastfile à maintenir.

$ npm i -g appship-ai
Lire le guide d'intégration

Workflow

Cinq commandes, du dépôt vide à l'App Review.

À configurer une fois par projet, tout vérifier, puis répéter les deux dernières à chaque release.

  1. Une fois par projet appship init

    Détecte votre framework, votre bundle id et votre nom de package, puis écrit release/ avec des modèles commentés et met à jour .gitignore.

  2. Avant chaque upload appship doctor

    Vérifie les outils, les clés, les limites de caractères, les tailles d'image et le texte provisoire, et échoue si une clé est commitée dans git.

  3. Première fois uniquement appship first-release

    Crée l'app iOS, envoie la fiche et App Privacy, et écrit CHECKLIST.md pour les étapes que les stores laissent en manuel.

  4. À chaque release appship upload --build

    Exécute votre commande de build, puis envoie l'.ipa vers TestFlight et l'.aab vers une piste Play, avec déploiement progressif.

  5. À chaque release appship submit

    Envoie le build iOS à l'App Review et promeut la release Android en production, après votre confirmation.

Ce qui est automatisé

Transparent sur ce que les stores permettent à un outil de faire.

Apple et Google laissent volontairement certaines étapes en manuel. appship automatise ce que leurs API permettent. Pour le reste, il vous fournit une checklist où vos réponses sont déjà remplies.

  • Automatisé appship s'en charge
  • Apple ID nécessite une connexion avec 2FA, donc pas sur la CI
  • Checklist pas d'API ; copiez vos réponses dans la console

Fonctionnalités

Tout ce qui entoure le binaire, pris en charge.

Une seule config par projet

Votre dépôt d'app ne reçoit qu'un dossier release/. La logique de release vit dans l'outil : mettre à jour appship met à jour tous les projets qui l'utilisent.

release/release.yml
app:
  name: "Word Bank"
  primary_locale: en-US
ios:
  bundle_id: com.ketch.wordbank
  artifact: "build/ios/ipa/*.ipa"
  build_command: "flutter build ipa --release"
android:
  package_name: com.ketch.wordbank
  track: internal
  rollout: 1         # 0.2 = 20% staged rollout
credentials:
  profile: ketch-studio

Les questions des stores, une seule fois

Classification par âge, conformité à l'export, droits sur le contenu, contact du reviewer. Écrivez les réponses dans questionnaire.yml ; appship renseigne ce que les API permettent et place le reste dans CHECKLIST.md.

release/questionnaire.yml
ios:
  export_compliance:
    uses_non_exempt_encryption: false
  content_rights:
    uses_third_party_content: false
  age_rating:
    gamblingSimulated: NONE
    violenceCartoonOrFantasy: NONE
    messagingAndChat: false
    ageAssurance: false

doctor repère les problèmes avant les stores

Limites de caractères, URL invalides, TODO oubliés, mauvaises tailles d'image, artefacts périmés, clés manquantes. Chaque problème s'accompagne de sa solution.

appship doctor
▸ iOS · store listing
  ✗ ios/metadata/en-US/subtitle.txt is 34 characters (max 30)
  ! ios/screenshots/vi has no 6.9"/6.5" iPhone screenshot
▸ Android · store listing
  ✗ images/icon.png is 1024x1024, expected 512x512

  ✗ 2 error(s), 1 warning(s)

Votre agent IA rédige le contenu des stores

Les skills fournis pour Claude Code, Codex et Antigravity rédigent les notes de version dans toutes les langues, créent les captures d'écran aux dimensions exactes des stores et remplissent les questionnaires des stores à partir de votre code. Ils n'écrivent que dans release/ ; vous relisez, puis vous envoyez. appship lui-même n'appelle jamais d'IA.

appship skills
▸ Claude Code: .claude/skills/
  ✓ app-content  installed
  ✓ release-notes  installed
  ✓ store-screenshots  installed
▸ Codex + Antigravity: .agents/skills/
  ✓ store-screenshots  installed
    Run: $store-screenshots (Codex)

Les clés restent hors de git

Les clés sont résolues depuis les variables d'environnement, puis release/keys/ (ignoré par git), puis un profil dans ~/.appship stocké avec le mode 600. Les mots de passe sont masqués dans --dry-run.

Compatible avec toutes les stacks

appship exécute votre commande de build et récupère l'.ipa et l'.aab. Les projets Flutter, React Native, Cocos Creator et natifs sont détectés à l'init.

Demande avant d'écrire

La soumission, l'envoi en production et l'écrasement d'une fiche en ligne demandent tous une confirmation. En CI, passez --yes explicitement.

Prêt pour la CI

Passez la clé .p8 en texte brut ou en base64 dans APPSHIP_ASC_KEY. Un workflow GitHub Actions prêt à l'emploi figure dans le guide d'intégration.

Prêt à publier ?

appship est distribué sur npm. Il vous faut Node.js 22+, fastlane et macOS pour les builds iOS (Android fonctionne aussi sous Linux).

$ npm i -g appship-ai
